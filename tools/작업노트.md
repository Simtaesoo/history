## 단원 하나를 만드는 순서

1. `assets/catalog.js`에서 단원의 차시·성취기준 확인.
2. 사진 찾기·받기 (위키미디어 공용)
   - `python3 tools/photo.py search "검색어"` → `python3 tools/photo.py get "File:…" m1/<단원>/<이름>`
   - 받은 뒤 `SHEET=<scratch>/a.png python3 tools/photo.py sheet m1/<단원>/<이름> …`로 모아 보고 **직접 눈으로 확인**. 맞지 않으면 바꾼다.
   - `assets/photo/credits.json`의 각 항목에 `credit`(한국어 짧은 출처 표기)를 넣는다. 슬라이드 출처 줄은 여기서 자동으로 만든다.
   - 잔혹한 사진 금지. 퍼블릭 도메인 우선. 인쇄 복제 허가가 필요한 사진(USC KADA 팸플릿)은 학습지에 넣지 않는다.
   - 위키미디어는 API가 막혀 있어 웹 페이지와 `action=raw`로 읽는다. 429가 나면 쉬었다가 다른 표준 크기(960 등)로.
3. `tools/decks/<과목>_<단원>.py` 작성: `LESSONS`(슬라이드), `WORKSHEET`(학습지). 형식은 `tools/build_deck.py`, `tools/build_ws.py` 맨 위 설명 참고. 앞 단원 파일(`m1_religion.py`)을 본보기로.
   - `python3 tools/build_deck.py tools/decks/….py` → `slidesN.html`
   - `python3 tools/build_ws.py tools/decks/….py` → `worksheet.html`
4. `sim.html`(차시마다 `<section class="panel" data-lesson="N">`, `assets/sim.css`·`sim.js` 공통)과 게임(`app-*.html`, 분류 게임은 `assets/game-sort.js`에 `window.R` 데이터만)을 손으로 작성.
5. `assets/catalog.js` 맨 아래 `FILES`에 등록 → `python3 tools/credits.py` → `python3 tools/check.py <폴더>`(JS 오류·링크·넘침) → `python3 tools/shot.py <png> "경로#해시|동작" …`로 **스크린샷 1장**만 보고 확인.
6. commit(아래 형식) → `git push origin HEAD:main`.

## 슬라이드 원칙 (samil.html 기준)

- 12장 안팎. 1장 표지(사진+큰 낱말), 2장 관통 발문(사실→해석→확장 사다리), 마지막 장 한 문장 쓰기(관통 발문으로 돌아오기).
- 화면에는 사진·낱말·질문만. 설명은 교사 메모(`note`)에: 질문 의도, 예상 답, 후속 질문.
- 사료 비판 질문을 차시마다 넣기: 누가 기록했나 / 누구에게 보여 주려 했나 / 사실일까 주장일까.
- 논쟁 있는 해석은 여러 관점을 메모에 함께. 연도·수치·인용은 출처 확인 후. 불확실하면 단정하지 않는다.
- 시뮬레이션 숫자가 기록이 아니면 화면에 ‘모형’이라고 밝힌다.
